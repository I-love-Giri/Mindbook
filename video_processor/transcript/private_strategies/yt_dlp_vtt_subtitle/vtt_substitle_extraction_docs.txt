This function tries to extract subtitles from a video using **yt-dlp**, save them as a **.vtt subtitle file**, read that file, and convert it into parsed subtitle text.


---

## Function Definition

```python
def _strat_ytdlp(self, url: str,
                 cancel_evt: Optional[threading.Event] = None) -> list:
```

### What it means

* `def` → defines a function.
* `_strat_ytdlp` → function name.
* `self` → this belongs to a class.
* `url: str` → expects a video URL string.
* `cancel_evt` → optional cancellation signal.
* `-> list` → function returns a list.

### Example

```python
result = obj._strat_ytdlp(
    "https://www.youtube.com/watch?v=abc123"
)
```

---

## Docstring

```python
"""
yt-dlp VTT subtitle extraction.

cancel_evt is checked before the (expensive) yt-dlp call so that if
another strategy has already won, this one exits without doing any
network work (cooperative cancellation, FIX 3).
"""
```

This is just a comment explaining:

* The function extracts subtitles using **yt-dlp**.
* Before downloading anything, it checks if another thread/process has already completed the task.
* If yes, it stops immediately.

---

## First Cancellation Check

```python
if cancel_evt and cancel_evt.is_set():
    return []
```

### What it does

Checks:

1. Is a cancellation event provided?
2. Has it been triggered?

If yes:

```python
return []
```

Return an empty list and stop.

### Example

Imagine 3 subtitle extraction methods are running:

```python
Method A
Method B
Method C
```

If Method A succeeds first:

```python
cancel_evt.set()
```

Then Method B and C will see:

```python
cancel_evt.is_set() == True
```

and immediately exit.

## Second Cancellation Check

```python
if cancel_evt and cancel_evt.is_set():
    return []
```

Why check again?

Because while downloading subtitles, another thread may have already succeeded.

Example:

```python
Thread A finishes
cancel_evt.set()
```

Then this thread stops before reading files.

## Parse VTT Content

```python

```

Pass subtitle text to a parser.

Example input:

```text

Hello everyone

00:00:04.000 --> 00:00:06.000
Welcome back
```

Parser may return:

```python
[
    "Hello everyone",
    "Welcome back"
]
```

or

```python
[
    {
        "start": "00:00:01",
        "end": "00:00:03",
        "text": "Hello everyone"
    },
    {
        "start": "00:00:04",
        "end": "00:00:06",
        "text": "Welcome back"
    }
]
```

depending on how `_parse_vtt()` is implemented.

## Complete Flow

```text
Video URL
    │
    ▼
Check cancellation
    │
    ▼
Create temp folder
    │
    ▼
Configure yt-dlp
    │
    ▼
Download subtitles (.vtt)
    │
    ▼
Check cancellation again
    │
    ▼
Find .vtt file
    │
    ▼
Read file contents
    │
    ▼
Parse subtitles
    │
    ▼
Return subtitle list
```

In simple terms: **this function uses yt-dlp to download English subtitles from a video, stores them temporarily as a `.vtt` file, reads that file, converts it into structured subtitle data, and returns the result.**
